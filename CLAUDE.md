# Findings (details and the step-by-step plan: PORTING.md)

- Targets: Windows, Linux, macOS, each x86_64 and arm64. macOS ships as one
  universal2 binary built on an arm64 runner.
- `NCX/` is ~26.7k lines of ObjC/ObjC++. `SyncComponent.mm`,
  `BluetoothEndpoint.mm` and `StoreInfo.mm` are in no Xcode target: dead, do
  not port.
- Layering: `ncx_core` (comms, model, dock, translators) has no FLTK
  dependency and is testable with `ncx-cli` and a fake Newton; `ui/` is
  FLTK only. Only the dock thread touches Refs.
- NCX needs only a small part of newton-framework: the object system, NSOF,
  pipes, packages, compression, ROM data, and QD drawing. This becomes the
  `newton_ncx` static library target there.
- Framework blockers: `typedef long Ref` (32-bit on Win64), the hand-defined
  `__LP64__`, GNU `.s` ROM data (all three fixed: 0.1, 0.1b), Quartz in
  `QDDrawing.cc` (fixed: 0.5, drawing on FLTK's current surface), and CMake
  that assumes it is the top-level project (fixed: 0.2).
- `Matt/NewtDump` (DockLink, MNP.cc, NTKTransport.cc, DES, FakeNewton) is
  the base for NCX's comms and tests. NTKTransport is POSIX-only so far.
- `.newtondevice` files are Core Data SQLite with a simple schema and NSOF
  blobs: read and write them with plain SQLite, keeping the same schema.
- FLTK gap: dragging files out of the app (file promises). v1 replaces it
  with Export/Save/Copy.

# Decisions (PORTING.md section 4)

- This branch is pure FLTK. `NCX/` and `NCX.xcodeproj` are reference only,
  never built or maintained.
- The ROM data is C generated by ResMaker (a CMake target in
  newton-framework); never edit `ROMData/for*/ROMData.c` by hand, change
  ResMaker and regenerate. No assembler in what NCX links, so Windows can
  use MSVC (clang-cl as fallback).
- Comms reuse newtdump's MNP/transport code (it descends from NCX). Use
  small chunks; NCX's `scrn`/`snap` extensions send chunks too large for
  real devices.
- Keep the `.newtondevice` Core Data SQLite schema byte-compatible.
- Rich-text export: RTF with embedded PNGs; on macOS also RTFD (its default
  for documents with pictures).
- No libical: an iCalendar (and vCard) reader and writer of our own (D10).
- Several document windows (one per .newtondevice file, drag and drop
  between them), no tabs; macOS: one system menu bar; Windows and Linux:
  the full menu in every document window; shortcuts go to the topmost
  window (D9).
